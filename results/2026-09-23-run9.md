# 实验记录：run9（结构性修复后从头训练 3000 万步）

日期：2026-09-22/23 · 硬件：M4 MacBook Pro，8 env，4200–4800 fps

## 结论

**用 1/5 的步数达到了 run6（1.6 亿步）的水平，掉落率更低，但能力上限没动。**
45° 下的 checkpoint 扫描从 500 万步开始就是平的。结构性修复换来的是样本效率，没有换来新能力。

另外，这轮分析发现 `diagnose.py` 有计数 bug：复盘三「HOLD 受限、59% overshoot」的结论是这个 bug 造出来的。
真实的瓶颈一直是 **REACH**（大约 70% 的目标连 15° 的锥都没进过）。详见 `orca_rl/README.md` 复盘四、复盘五。

## 配置

    python -m orca_rl.train --name run9 --timesteps 30_000_000 --n-envs 8

相对 run1–run8 的改动（都是新默认值）：

- reset 时先让方块落稳，再抽目标。旧 reset 下，零策略在 30° 难度有 26% 的 episode 白拿一次成功。
- 观测里加入伺服目标，54 → 71 维。run6/run8 有 77% 的时间伺服目标顶在 ctrlrange 边界上。
- PPO `batch 1024 / lr 1.5e-4`（原来是 256 / 3e-4）。旧设置下 run8 的 628 次更新全部在第一个 epoch 就被 `target_kl` 截停。
- 每个目标 150 步超时；课程改按目标尝试的成功率调整（≥0.55 升，≤0.25 降）；势函数用角度而不是 cos；γ 0.995。
- `spin_penalty=0.05`、`align_bonus=0.1`。**这两项是依据有 bug 的诊断加的**，run10 就是去掉它们的对照组。

## 评估协议 v2

`--goal-angle {30,45,60} --episodes 100 --seed 0`，确定性策略，hold 10 步，目标超时 150 步。
`--vecnormalize` 现在会自动找到对应的文件，包括 checkpoint 的 `ppo_vecnormalize_<N>_steps.pkl`。

**和 v1 不可比。**v2 下 reset 会先让方块落稳，并且每个目标有 150 步超时，所以一个 episode 里可以尝试好几个目标。
跨 run 比较请看「目标成功率」，不要看 solves/episode。下表 run6 的数据是在 v2 下重新测的。
