# 实验记录：run10（run9 去掉 spin_penalty 和 align_bonus）

> **更正（2026-09-24）：**本文「刹车项用 REACH 换转化率」这个机制解释，在 seed 噪声以内站不住。和 run10 完全相同设置、只换了 seed 的 run12，45° 进锥率就是 33%。见 `2026-09-24-run11-13.md`。去掉这两项的决定仍然成立。

日期：2026-09-23 · 硬件：desktop i9-11900F（WSL2，14 线程），14 env，2100–2600 fps

## 结论

**关掉这两项，三个难度全部更好，60° 从 20% 提到 28%。**这两个奖励项确实教会了策略刹车（转化率 68% 对 44%），
但它们压低了 REACH（进锥率 33% 对 44%）。瓶颈本来就在 REACH，所以这笔交换是亏的。默认值已经改回 0。

## 配置

    python -m orca_rl.train --name run10 --timesteps 30_000_000 --n-envs 14 --n-steps 292 \
        --device cpu --spin-penalty 0 --align-bonus 0

和 run9 只有两处不同：

- **奖励：**去掉 `spin_penalty` 和 `align_bonus`。这是要测的变量。
- **rollout 形状：**14 env × 292 步 = 4088 条样本（run9 是 8 × 512 = 4096）。每次更新的样本量几乎一样，但每条轨迹截得更短，是一个小混杂因素。

9.72M 步时，WSL 的发行版被关闭，训练被硬杀。之后从 9.5M 步的 checkpoint 续训，
正确加载了 `ppo_vecnormalize_9499924_steps.pkl`，一共损失约 22 万步。

## 终点对比（协议 v2：100 episode，seed 0，所有模型都在同一台 Mac 上评估）

| | 训练步数 | 30° | 45° | 60° | 掉落（30° / 45° / 60°） |
|---|---|---|---|---|---|
| run6 | 1.6 亿 | 38% | 31% | 17% | 7% / 10% / 12% |
| run9 | 3000 万 | 44% | 32% | 20% | 3% / 4% / 4% |
| **run10** | **3000 万** | **49%** | **39%** | **28%** | 6% / 2% / 1% |

每个难度下大约有 260 次目标尝试。run10 相对 run9 的差距约为：30° 1.3 个标准误，45° 1.8 个，60° 2.2 个。
三个难度方向一致，checkpoint 扫描从 1000 万步开始也一直更高。但**只有一个 seed**。

## 瓶颈分解（修复后的 diagnose，60 episode）

| | run9 @45° | run10 @45° | run9 @60° | run10 @60° |
|---|---|---|---|---|
| 进锥率（REACH） | 33% | **44%** | 16% | **25%** |
| 转化率（CONVERT） | **68%** | 44% | **67%** | 44% |
| 未解开目标最近距离，中位数 | 20.5° | 17.3° | 32.2° | 30.6° |
| 守不住的原因里 overshoot 占比 | 68% | 94% | 67% | 84% |
| 方块在手里的时间 | 85% | 100% | 74% | 100% |

去掉刹车项之后，overshoot 变成了真实存在、而且占绝对多数的失败原因（这次的数字来自修复后的 diagnose）。
所以「刹车」本身是有价值的，问题出在奖励的形式：它让策略在靠近目标时变得犹豫。

## 下一步

1. **掉落后不结束 episode**，针对 REACH（long-1e8 记录里的下一步 #2）。
2. 重新设计刹车信号，目标是**提高转化率但不牺牲 REACH**。例如只在成功那一刻按角速度给奖励
   （方块停得越稳，奖励越多），而不是在锥内每一步都罚角速度，这样靠近目标本身不会被罚。
3. 结论只来自一个 seed。在它成为后续所有实验的基线之前，值得换一个 seed 再跑一次 run10。
