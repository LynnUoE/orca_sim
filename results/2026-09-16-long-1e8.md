# 实验记录：long-1e8（1 亿步基线）

日期：2026-09-16 · 硬件：i9-11900F 8C/16T + 32 GB（RTX 3080 未参与计算）

## 结论

**五倍算力（2e7 → 1e8）没有带来任何操作能力的提升。** 策略最大化奖励的方式是「抱住方块不掉、耗满 episode」，而不是学会翻转。课程难度净倒退。

**不要再靠加算力推进。下一步是改奖励结构和课程规则。**

## 配置

python -m orca_rl.train --n-envs 14 --device cpu --timesteps 100000000 --name long-1e8


`--device cpu` 比 cuda 快 32%（3603 vs 2446 fps）—— 策略是 54→17 的小 MLP，GPU 的 host↔device 传输是纯开销，SB3 自己会警告。吞吐全程 3558 → 2878 fps（约 19% 下降，疑似长时间满载热降频）。

## 评估协议 v1

`--goal-angle 60 --episodes 100 --seed 0 --deterministic --hold-steps 10`，必须传 `--vecnormalize`。

不钉死难度的话课程在评估期间还在自适应，跨 run 不可比（同一模型：自适应 0.76 solves/ep vs 固定 60° 的 0.17）。

## Checkpoint 扫描（固定 60°，每档 50 episode）

原始数据见 `long-1e8-sweep.tsv`。

| 阶段 | solves/ep 均值 | return 均值 |
|---|---|---|
| 前 5 个（5–25M） | **0.192** | +1.14 |
| 后 5 个（80–100M） | **0.136** | +0.39 |

**9500 万步额外训练，固定难度下解题能力没涨，甚至略降。**

## 与 2e7 基线的对照

| | solves @60° | drop @60° | return @60° |
|---|---|---|---|
| 2e7 | 0.17 | 32% | −0.20 |
| 1e8 终点 | **0.16** | **0%** | **+1.52** |

**解题次数一模一样，掉落率归零，return 的全部改善来自「不掉」。**

## 分析：两个结构性原因

### 1. 课程的升降阈值不对称

规则是「≥2 solves/ep 则 +5°，≤0.5 则 −5°」。而策略全程在 **0.45–0.70** 之间 —— 上界 2.0 永远够不着，下界 0.5 正好卡在工作区间中央。**只会降不会升**，一有波动就往下掉，形成「解得少 → 目标变简单 → 学习压力更小」的下行螺旋。

### 2. 掉落的真实惩罚远不止 −5

[事故复盘](../claude/orcahand-ppo-postmortem.md)把显式惩罚从 −10 改成 −5，但**掉落仍然终止 episode**。在第 50 步掉，就损失后面 350 步的 shaping 和成功机会；按 400 步挣 5.4 算，那是额外约 −4.7 的机会成本。**有效惩罚仍然接近 −10**，和修复前一样。复盘只修了看得见的那一半。

### 3. 视频证据（2026-09-14，2e7 模型）

- 方块被楔在手指和掌面之间，掌面约 45° 倾斜
- **掉落发生在手指张开的那一刻** —— 逐帧可见：稳定楔住 → 手指外展 → 方块沿掌面下滑 → 脱手。不是「动作太猛甩出去」，是「松手重抓时没接住」
- 用红面像素数当朝向代理：有 7.5 秒手指大幅开合而方块几乎不动
- 但零动作策略在 100 episode × 400 步里 **0% 掉落** → **稳定域是存在的**，策略只是不知道边界在哪

## 下一步

1. **修课程阈值** —— 上下界对称夹住真实工作区间（如 0.8 升 / 0.3 降），且不允许降到起点以下
2. **掉落不终止 episode** —— 方块放回手里、扣 −5、继续跑。这样惩罚才真的是 −5，策略也能学「掉了之后怎么办」
3. **接触数约束** —— 奖励里加「保持 ≥3 接触点」或惩罚接触点骤降，给它「正在离开稳定域」的信号
4. 待补：终点模型在 30°/45° 上的同难度对照

1 和 2 都是几行代码，应该先做 —— 3 的效果会被它们的偏差掩盖。

## 教训

这是继 [v1 复盘](../claude/orcahand-ppo-postmortem.md)之后**第二次**出现「曲线全绿但学的不是正确的东西」。v1 是 `ep_rew_mean` / `explained_variance` / `approx_kl` / `clip_fraction` 全健康但零进展；这次是它们全健康、return 还在涨，而固定难度的真实能力零增长。

**课程的 `goal_angle_deg` 是自我报告，不是能力度量。** 必须用固定难度评估 + checkpoint 扫描才看得出来。
