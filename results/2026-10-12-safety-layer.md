# 2026-10-12 转方块策略接上 Orca_safety 安全层

把训练好的 v1 转方块策略（run22、run23，目标旋转向量 + 指尖观测）直接套上组员的碰撞安全层
（`Orca_safety`，CBF-QP，v1 右手 108 对连杆）。**策略没有重新训练**，训练时也没有任何安全层。

## 做法

- 每个控制步，环境把动作变成 17 个关节目标 `q_nominal`。安全层开时，它和实测关节角一起进入
  `CBFSafetyFilter`，输出的 `q_safe` 才发给舵机。
- `q_safe` 同时成为环境的「上一步目标」：相对动作从实际下发的目标继续积分，不会顶着滤波器越积越多；
  策略的观测里看到的也是它。
- 两种模式都在每步之后用同一个碰撞模型测手的自间距，所以「关」就是被动基线。
- 同一个策略、同一批复位 seed（0–99）、45° 固定目标、每回合 400 步、确定性动作。
- 安全层只认识手。方块不在约束里，方块可以把手指推到一起。
- 几何核对：URDF 模型与 MuJoCo 的连杆间距离在 5 个姿态上最大相差 4e-17 m。

命令：`python -m orca_rl.evaluate_safety --model <run>/final_model.zip --goal-angle 45 --episodes 100 --out results/safety/<name>.json`

## 结论

1. **没有安全层时，策略大部分时间都在挤手指。** 57–74% 的步数里有不同手指的连杆相互接触，
   run23 主要是中指–无名指近节，run22 主要是无名指–小指近节。用 MuJoCo 自己的接触检测交叉验证
   （run23，3 个回合）：不同手指之间有接触的步数 59%，碰撞模型报 56%，穿透深度中位 0.5 mm。
   训练时没有任何项约束手指间距，方块托在掌心时把手指并拢是自然的结果。
2. **安全层把自碰撞基本消除了，掉落也变少。** 碰撞步数降到 0–0.12%，掉落 5%→0%、9%→3%。
   但间距仍有 19–30% 的步数低于 5 mm：滤波器约束的是下发的目标，方块的接触力仍会把手指推近。
3. **成功率的代价：run23 掉 9 个百分点，run22 掉 3 个。** 前者超出噪声，后者在噪声内。
   滤波器几乎每一步都在改目标（97%），18–29% 的步数直接回退。
4. **把间距调小并不能把成功率换回来。** 5 / 2 / 1 / 0.2 mm 的成功率是 34 / 36 / 35 / 38%，彼此在噪声内，
   都低于关的 43%；而 0.2 mm 时碰撞步数已回到 2.9%。代价主要来自「不许手指并拢」本身和回退行为，
   不是 5 mm 这个数值。要把成功率拿回来，需要让策略在训练时就知道这个约束。
5. **离实时还很远。** 仓库里的滤波器每步 65–75 ms（有限差分梯度），控制周期是 10 ms。
   `Orca_safety/delay` 记录的解析梯度版本约 20 ms，尚未进入 `src/`。这里的评估是离线的：
   仿真等滤波器算完才走下一步。

## 下一步的选择

> 更新（10 月 13 日）：第二条「带着安全层训练」已经做了一次微调实验，见 `2026-10-13-safety-finetune.md`。

- 把手指间距做成奖励或观测，重新训练，让策略自己不挤手指（不需要在训练循环里跑滤波器）。
- 带着安全层训练。按现在每步约 70 ms 算，一个 3000 万步的 run 约需 580 CPU 小时（14 个并行环境约 40 小时），要先把滤波器提速，
  或者训练时用便宜的近似（例如只查相邻手指的几对连杆）。
- 安全层目前不包含同一手指内部和手掌的连杆对，也不知道方块；这里的「安全」只指手指之间。

## 复现

```bash
# 在 Orcahand-Safe-Assembly 旁边
git clone https://github.com/orcahand/orcahand_description.git
uv venv safety_venv --python 3.11 --seed
safety_venv/bin/pip install "mujoco==3.12.0" -r Orcahand-Safe-Assembly/Orca_rl/requirements.txt \
    -e "./Orcahand-Safe-Assembly/Orca_safety[geometry,safety]"   # 用 venv 自带的 pip；uv pip 不接受 requirements.txt 里的可编辑 git 安装
cd Orcahand-Safe-Assembly/Orca_rl
../../safety_venv/bin/python -m orca_rl.evaluate_safety --model models/run23/final_model.zip \
    --goal-angle 45 --episodes 100 --out results/safety/run23_45deg.json
../../safety_venv/bin/python -m orca_rl.record_safety --model models/run23/final_model.zip \
    --goal-angle 45 --seeds 0 1 --out safety_off_on.mp4
```

100 回合在 M4 Mac 上 8 进程：关约 1.5 分钟，开约 8 分钟。每回合的原始数据在 `results/safety/*.json`。
间距扫描用 `--safety-config` 指向改过 `safe_distance` / `activation_distance` 的 `v1_right.yaml` 副本。
对比视频：`demo_videos/6_cube_v1_safety_off_on.mp4`。

模型文件在 `models/`；安装步骤已在空目录里从头验证过，详见 `../SAFETY.zh-CN.md`。结果与 MuJoCo 版本有关：本文数字用的是 3.12.0。
