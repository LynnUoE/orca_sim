# 实验记录：run22 / run23 / run24（换成 v1 手）

日期：2026-09-27 · run22、run24 在 Mac 上跑，run23 在 desktop 上跑。都是 14 env × 292 步、3000 万步，`--version v1`。

实体手是 ORCA v1，而 run1–run21 都是在 v2 上训练的。两者都是 17 个执行器，但顺序和关节范围都不同
（v1：手腕、拇指 ×4、食指、中指、无名指、小指；v2：手腕、小指、无名指、中指、食指、拇指），所以必须在 v1 上重新训练。

| run | seed | 配置 |
|---|---|---|
| run22 | 0 | v1 + 旋转向量 + 指尖与接触（即 v2 上最好的 run20 / run21 配置） |
| run23 | 1 | 同 run22 |
| run24 | 0 | v1 基线（只有伺服目标观测，同 run10） |

## 结论

1. **旋转向量和指尖特征在 v1 上同样有效**：seed 0 配对，每个难度高出 14–22 个百分点。
2. **v1 这个任务本身难得多**：v1 基线 45° 只有 22%（v2 基线 38%），课程一直贴在 25° 下限；
   加了特征的 v1 也只到 v2 基线的水平（45° 约 41%）。
3. 最可能的原因是 **v1 场景里方块离手指太远**（见下），需要按实体手的实际摆放调整场景。这还只是解释，没有验证。

## 为什么 v1 更难

两个版本用的是同一个方块（边长 3.6 cm，80 g），但 v1 的手指更长：

| | v2 | v1 |
|---|---|---|
| 方块落稳后高度 | 0.174 m | 0.179 m |
| 初始时指尖到方块中心（拇指 → 小指） | 6.9 / 7.3 / 7.9 / 7.9 / 7.7 cm | 8.6 / 15.3 / 15.7 / 14.8 / 12.8 cm |
| 初始时碰到方块的手指 | 中指 | 没有 |

45° 下的瓶颈分解（60 episode）：run24 只有 23% 的目标进过容差锥，run22 为 40%；进锥后能守住的比例两者都是 66–67%。
难点在「够不到」，和上面的几何差异一致。

## 还缺的

- v1 基线只有 seed 0，按「两个 seed 都赢」的规则还需要一个 seed 1 的 v1 基线。
- v1 场景（方块尺寸、质量、摆放位置、手的姿态）需要和实体手对齐后再训练，否则训练的是一个比实物更难的任务。
